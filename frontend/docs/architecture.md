# Архитектура frontend

## Стек

- Expo SDK 58, React Native 0.88, React 19, TypeScript 6 (`strict: true`).
- Навигация: Expo Router.
- Платформы: iOS, Android, web.
- Данные с сервера: TanStack Query + axios.
- Клиентское состояние: Zustand.
- UI и дизайн-система: React Native Paper

## Структура (feature-based)

```
src/
  app/                # только тонкие маршруты Expo Router
    workouts/index.tsx  # export { default } from '@/features/workouts/screens/WorkoutListScreen'
  features/
    workouts/         # пример фичи
      screens/        # экраны, подключаются в app/
      components/     # компоненты только этой фичи
      hooks/          # хуки фичи, в т.ч. useQuery / useMutation
      api/            # запросы к серверу (workouts.api.ts) и query keys (keys.ts)
      store/          # Zustand-стор фичи
      types.ts
      index.ts        # публичный интерфейс фичи
  shared/
    api/              # экземпляр axios, общие типы (пагинация, ошибки)
    components/       # обёртки над Paper и UI без бизнес-логики
    hooks/
    lib/              # утилиты
    theme/            # тема Paper (светлая и тёмная): цвета, шрифты
```

Подпапки фичи создавать, только когда в них появляется код.

## Правила

- **Роуты:** в `src/app/` только реэкспорт экрана и `_layout.tsx`. Логики и вёрстки там нет.
- **Слои:** `app → features → shared`. `shared` не импортирует из `features` и `app`, фича не импортирует из `app`.
- **Границы фич:** из другой фичи импортировать только через её `index.ts`, не `@/features/a/components/...`. Внутри своей фичи импорты напрямую, не через её `index.ts`.
- **`index.ts` фичи:** экспортирует только нужное снаружи (экраны, несколько хуков, типы).
- **Общий код двух фич:** выносить в `shared/`. Если фичи не живут друг без друга, объединить.
- **Запросы к серверу:** только в файле `api/<name>.api.ts` фичи (чистые функции поверх axios из `shared/api/`, без React). Хуки, компоненты и экраны не вызывают axios напрямую и не собирают URL. Суффикс `.service.ts` зарезервирован под будущие сервисы с логикой.
- **Хуки данных:** `useQuery`/`useMutation` в `hooks/` вызывают только функции из `<name>.api.ts`. Query keys в `api/keys.ts`.
- **Кэш:** данные с сервера живут только в кэше TanStack Query, в Zustand не дублируются.
- **Zustand:** стор на фичу, только клиентское состояние (UI, черновики, фильтры). Глобальный стор только для сквозного (например, сессия), лежит в `shared/`. В компонентах подписываться через селекторы.
- **Типы:** ответы API в `features/<name>/types.ts`, общие в `shared/api/`.
- **UI (Paper):** использовать готовые компоненты Paper, собственную вёрстку писать только когда подходящего нет. `PaperProvider` с темой подключается один раз в корневом `_layout.tsx`. Цвета и шрифты брать из темы (`useTheme()`), не хардкодить. Если компонент Paper нужно часто настраивать одинаково, делать обёртку в `shared/components/`.
- **Импорты:** через алиас `@/`.

## Открытые решения

- Совместимость Paper с Expo SDK 58 / RN 0.88 и React Compiler: проверить при установке 
- Аутентификация и защита маршрутов.
- Хранение на устройстве, оффлайн.
- Типы из OpenAPI: вручную или генерация.
- Формы и валидация.
- Тестирование.
